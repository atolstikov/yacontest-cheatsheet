# Метрика по файлу предсказаний

Используйте рецепт, если участник сдаёт готовые предсказания, а Контест рассчитывает метрику по скрытым ответам. Запуска модели участника в этом рецепте нет.

## Что сдаёт участник

CSV без заголовка: ровно 3140 строк и один столбец бинарных предсказаний. Скрипт сборки сохраняет посылку как `data.csv`. [score.py](score.py) рассчитывает F1 и преобразует его в баллы:

```text
балл = clip((F1 - 0.5) / 0.16, 0, 2)
```

Для другого датасета согласованно измените `N_ROWS`, формат данных и формулу в `score.py`, а также условие задачи.

## Подготовьте скрытые ответы

Создайте `true_answers.csv` с заголовком и одним столбцом правильных меток в порядке строк предсказаний. Для текущего примера нужно 3140 меток. Файл не входит в репозиторий; не добавляйте скрытые ответы в публичные материалы.

Разместите файл в `./contest-assets/ml-score-prediction/true_answers.csv` относительно корня репозитория и исключите каталог данных из Git. Проверьте и соберите рецепт:

```sh
python _packaging/package_recipe.py --check ml-score-prediction --assets ./contest-assets
python _packaging/package_recipe.py ml-score-prediction --assets ./contest-assets
```

Возьмите архив `dist/ml-score-prediction.zip`.

## Настройте задачу

Выберите `PROBLEM_WITH_CHECKER`, компилятор `make` и образ с Python, numpy, pandas и sklearn. Выделите достаточно памяти для загрузки библиотек; начните с 512 МБ и проверьте контрольной посылкой.

| Настройка | Значение |
| --- | --- |
| Ввод | Не используется, stdin выключен |
| Вывод | файл `answers.csv`, stdout выключен |
| Создание файлов | Разрешено |
| Файлы компиляции | `Makefile`, `build.sh`, `run.sh`, `score.py`, `true_answers.csv` |
| Файлы запуска | `run.sh`, `score.py`, `true_answers.csv` |
| Тип чекера | `TESTLIB_EXITCODE_CHECKER`, «Чекер выставляет баллы» включено |
| Окружение и файл чекера | C++ с testlib.h; `pointscmp.cpp` |
| Постпроцессор | Python; `postprocessor.py` |
| Тесты | Одна пустая пара `tests/01` и `tests/01.a` |
| Монитор | `SCORING` |

Оставьте ровно один активный тест: скрипт обрабатывает весь CSV за один запуск, а постпроцессор суммирует баллы разных тестов. Имя выходного файла в настройках должно совпадать с `OUT` в `score.py`.

## Как считается результат

`score.py` записывает число или текст ошибки в `answers.csv`. Чекер передаёт число через `quitp`, а текст ошибки возвращает как WA. Постпроцессор переносит балл теста в итог посылки. Нулевая метрика может дать OK/0 — это допустимый результат.

## Проверьте результат

Подготовьте CSV, совпадающий со скрытыми метками: ожидайте OK/2. Отправьте CSV неправильной формы: ожидайте WA/0. Для промежуточного балла измените часть меток и сверьте результат с формулой.

Если участник не видит причину WA, включите «Вывод чекера» в отчёте. При пустом выходе проверьте `answers.csv` и отключённый stdout. При ML проверьте лимит памяти и зависимости образа.

[Общие правила загрузки и проверки](../README.md#настройте-задачу). ZIP содержит файлы; роли, тесты и настройки назначьте отдельно в админке.
