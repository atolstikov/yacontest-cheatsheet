# yacontest-cheatsheet

Рецепты задач для [Яндекс Контеста](https://contest.yandex.ru). Сверено с [документацией администратора](https://admin.contest.yandex.ru/docs/ru/) 1 ноября 2026 года.

## Общий контракт

Задачи ниже, кроме вопроса с вариантами и правил видимости, имеют тип `PROBLEM_WITH_CHECKER` и компилятор `make`. Поведение задаёт `Makefile`: цель `build` готовит посылку, цель `run` выполняется на каждый тест. Официальный разбор того же приёма: [проверка своим скриптом](https://admin.contest.yandex.ru/docs/ru/examples/advanced-usage/default-tests-for-language).

- В `Makefile` отступы команд — табуляция. Пробелы дают `CE Makefile: *** missing separator`.
- В файлы компиляции первым загружают `Makefile`. В файлы запуска первым загружают `run.sh`. Исполняемый файл чекера и постпроцессора тоже идёт первым.
- Имя файла посылки лежит в `$filename`. Копируйте его через файл, имя которого выдаёт `mktemp`. Фиксированное имя временного файла может совпасть с посылкой, и `cat` обнулит её до чтения. Прямое переименование в целевой файл так же теряет посылку, если участник уже прислал её под этим именем.
- Хотя бы один тест обязателен, иначе `run` не запустится. Для юнит-тестов и метрики хватает пустых `tests/01` и `tests/01.a`.
- Скрипты и постпроцессор — только с переводами строк LF. CRLF постпроцессор не запускается.
- Чекер на Python получает три пути: вход, вывод участника, эталон. Тип чекера — `TESTLIB_EXITCODE_CHECKER`. Коды возврата: `0` OK, `1` WA, `2` PE. Остальные коды документация не задаёт; такой выход обычно превращается в Crash, «не удалось протестировать».
- Опция «Чекер выставляет баллы» берёт первое число первой строки вывода и только при вердикте OK. В чекере на C++ то же делает `quitp`. Описание: [чекеры](https://admin.contest.yandex.ru/docs/ru/problem/checkers).
- Постпроцессор запускается один раз после всех тестов и вердикт не меняет. Первая строка его вывода — число, это балл посылки; следующие строки — лог. JSON со stdin читайте через `json.load`: пример документации с `input()` обрывается на первой строке, а сам пример JSON многострочный. Описание: [постпроцессоры](https://admin.contest.yandex.ru/docs/ru/problem/postprocessors).
- Эти баллы попадают в таблицу только при мониторе `SCORING`. Текст участнику включают отдельно: «Вывод чекера» и «Вывод постпроцессора» в [отчёте по посылке](https://admin.contest.yandex.ru/docs/ru/guide/contest/testing-and-report).
- Если балл зависит от числа пройденных тестов, выключите «Прерывать тестирование при первой ошибке» и такое же прерывание внутри набора тестов.
- `yc-invoke` не запускает постпроцессор и не умеет чекер без компилятора, только по shebang.

Публичная документация описывает компилятор `make` и вызов `python3` из его образа. Имена `python-lyceum` и `yandexdataschool` в ней больше не встречаются: наличие `numpy`, `pandas`, `sklearn`, `flask`, `requests` или `flake8` проверяйте по списку компиляторов соревнования. Отдельный компилятор на одну задачу задаётся в индивидуальных настройках этой задачи внутри соревнования.

Условие лучше писать как Markdown + KaTeX. Лимиты времени и памяти система показывает сама.

Рабочие заметки — в каталоге `notes/`.

## Рецепты

- `ml-score-prediction` — метрика по сданному файлу. Балл ставит чекер через `quitp`, постпроцессор переносит его в балл посылки.
- `run-unittest-python` — юнит-тесты функции участника. Совпадает с официальным примером своего скрипта; штраф за позднюю сдачу выключен, пока не задан `DEADLINE`.
- `db-sqlite` — скрипт с запросом к SQLite. Чекер сам выполняет эталонный запрос, постпроцессор ставит 100 только если прошли все тесты.
- `network-http-requests` — HTTP-запрос к серверу задачи. Ответ сравнивает стандартный `cmp_file`.
- `test-problem` — вопрос с одним или несколькими вариантами и частичные баллы своим чекером.
- `visibility-rules` — когда какую задачу показывать. Пример переписан на поля из текущего описания правил.
