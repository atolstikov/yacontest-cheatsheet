# yacontest-cheatsheet

Рецепты нестандартных задач для [Яндекс Контеста](https://contest.yandex.ru): проверка данных метрикой, юнит-тесты, работа с SQLite, HTTP-клиенты и серверы, вопросы с вариантами ответа.

## Выберите рецепт

Откройте инструкцию подходящего рецепта. Используйте её для настройки файлов, окружения, ввода/вывода и оценивания.

| Рецепт | Что сдаёт участник | Проверка | ZIP только файлов |
| --- | --- | --- | --- |
| [Метрика по CSV](ml-score-prediction/readme.md) | Файл с предсказаниями | Расчёт метрики по скрытым ответам | Да; подготовьте файл ответов отдельно |
| [Юнит-тесты](run-unittest-python/readme.md) | Python-модуль | Тесты функций с начислением баллов | Да |
| [Запрос к SQLite](db-sqlite/readme.md) | Python-скрипт | Сравнение результата запроса с эталоном | Да |
| [HTTP-клиент](network-http-requests/readme.md) | Python-скрипт | Запросы к локальному серверу задачи | Да |

## Перенесите рецепт в Контест

Выберите удобный способ:

1. Запросите у владельца сборника доступ к готовой задаче и клонируйте её в админке.
2. Соберите самостоятельный архив из исходников и импортируйте его через «Задачи → Загрузить задачу → YANDEX»:

```sh
python -m pip install -r _packaging/requirements.txt
python _packaging/package_problem.py db-sqlite
```

Загрузите `dist/db-sqlite.yandex.zip`. В нём уже есть условие, файлы, тесты и настройки задачи. После импорта редактируйте свою копию и добавьте её в соревнование. Образ запуска и настройки соревнования проверьте отдельно.

[Полная инструкция по клонированию, сборке и импорту](_packaging/README.md). Для семи импортируемых рецептов есть `statement.md` с условием участника. Готовые архивы в Git не хранятся.

## Соберите только файлы

Установите Python 3.10 или новее. Для упаковщика дополнительные пакеты не нужны; зависимости самого рецепта установите в выбранном образе Контеста.

Запускайте команды из корня репозитория. Сначала проверьте выбранные рецепты, затем соберите архивы:

```sh
python _packaging/package_recipe.py --check db-update network-http-server
python _packaging/package_recipe.py db-update network-http-server
```

Возьмите готовые ZIP из `dist/`. Упаковщик использует манифесты `package.json`: включает перечисленные файлы, проверяет пары тестов, пути и синтаксис Python, переводит текст в LF и сохраняет бинарные данные без изменений. Авторские решения и README в архивы не входят.

Для ML-рецепта подготовьте `true_answers.csv`. Передайте каталог дополнительных данных через `--assets`; структура должна быть такой:

```text
contest-assets/
└── ml-score-prediction/
    └── true_answers.csv
```

Проверьте и соберите все рецепты с манифестом:

```sh
python _packaging/package_recipe.py --check --all --assets ./contest-assets
python _packaging/package_recipe.py --all --assets ./contest-assets
```

Относительный путь считается от текущего рабочего каталога. Если каталог данных находится внутри репозитория, исключите его из Git через `.git/info/exclude`.

При ошибке проверки любого выбранного рецепта упаковщик не записывает архивы всей партии. Рецепты без манифеста в `--all` не входят. Проверка файлов не заменяет запуск решения в образе Контеста.

При изменении упаковщика запускайте его тесты:

```sh
python -m unittest discover -s _packaging/tests -v
```

## Настройте задачу

1. Создайте задачу или копию шаблона. Перед изменением существующей задачи проверьте, какие наборы и соревнования её используют.
2. Для программных рецептов выберите тип `PROBLEM_WITH_CHECKER` и компилятор `make`. Выберите образ с зависимостями из README рецепта. Для вопроса с вариантами используйте тип `TEST_PROBLEM`.
3. Загрузите ZIP в корень файлов задачи. Сверьте список файлов и удалите ненужные старые файлы: загрузка перезаписывает совпадающие пути, но не удаляет отсутствующие в архиве.
4. Назначьте файлы компиляции, запуска, чекера и постпроцессора по README рецепта и спискам ролей в `package.json`. Первым укажите `Makefile` для компиляции, `run.sh` для запуска и исполняемый файл для чекера и постпроцессора. Для интерпретируемых скриптов выберите соответствующее окружение.
5. Настройте ввод/вывод, разрешение создания файлов, лимиты и активные наборы тестов. Добавьте хотя бы один тест; если вход не используется, создайте пустую пару входа и ответа.
6. Возьмите условие из `statement.md` выбранного рецепта и адаптируйте его. Укажите контракт решения, формат данных и правила начисления баллов. Лимиты задайте в настройках задачи.
7. Добавьте задачу в набор соревнования и сохраните изменения.

ZIP переносит файлы. Роли файлов, компиляторы, тестовые наборы и остальные настройки задайте в админке отдельно.

## Настройте оценивание

- Для стандартного сравнения используйте `STANDARD_CHECKER` и `cmp_file`. Для своего чекера выберите `TESTLIB_EXITCODE_CHECKER`; возвращайте `0` для OK, `1` для WA и `2` для PE.
- Передавайте своему чекеру три пути: вход, вывод участника, эталон. Если чекер начисляет баллы, включите «Чекер выставляет баллы» и печатайте число в начале первой строки при вердикте OK. В C++ используйте `quitp`.
- Для итогового балла по нескольким тестам подключите постпроцессор. Читайте JSON из stdin через `json.load` и печатайте итоговое число первой строкой. Постпроцессор меняет балл, но не вердикт.
- Для оценки по доле пройденных тестов отключите «Прерывать тестирование при первой ошибке» в задаче и внутри набора тестов. Исключите примеры из формулы, если они не должны приносить баллы.
- Выберите монитор `SCORING`. Явно задайте, какая посылка идёт в зачёт: последняя или лучшая.
- Настройте доступность отчёта участнику. Включайте «Вывод чекера» и «Вывод постпроцессора», только если их содержимое должно быть видно участнику.

Подробнее: [чекеры](https://admin.contest.yandex.ru/docs/ru/problem/checkers), [постпроцессоры](https://admin.contest.yandex.ru/docs/ru/problem/postprocessors), [отчёт по посылке](https://admin.contest.yandex.ru/docs/ru/guide/contest/testing-and-report).

## Проверьте перед использованием

1. Откройте сохранённое условие со стороны участника и проверьте формат сдачи.
2. Отправьте правильное решение и сверьте вердикт и максимальный балл.
3. Отправьте заведомо неверное решение и проверьте ожидаемую ошибку или нулевой балл.
4. Для частичного зачёта отправьте решение, проходящее часть тестов, и сверьте расчёт.
5. Проверьте строку и итоговый балл в мониторе обычным аккаунтом участника. Учитывайте выбранную стратегию зачётной посылки при отрицательных проверках.

## Устраните ошибки

| Симптом | Действие |
| --- | --- |
| CE, `missing separator` | Замените пробелы перед командами `Makefile` на табуляцию. |
| CE, нет модуля или команды | Проверьте зависимости в выбранном образе. Вызывайте `python3` из PATH. |
| flake8 падает с `Errno 38` | Используйте CLI `python3 -m flake8 --jobs=1`, чтобы отключить multiprocessing. |
| Python пытается выполнить shell-обёртку | Выберите Python-скрипт исполняемым файлом чекера в Python-окружении. |
| SQLite не разрешает запись | Скопируйте исходную базу во временный каталог и изменяйте копию. |
| Crash или «не удалось протестировать» | Проверьте активный тест, окружение и файлы чекера, затем его код выхода. |
| OK, но балл равен нулю | Проверьте передачу баллов чекера и постпроцессор. Задайте явную формулу начисления; одного максимального балла может быть недостаточно. |
| Частичный балл меньше ожидаемого | Отключите оба прерывания при первой ошибке и проверьте состав тестов в формуле. |
| Баллы есть в отчёте, но отсутствуют в мониторе | Проверьте `SCORING`, генерацию и видимость монитора, состав участников и зачётную посылку. Повторите проверку обычным участником. |
| Запускаются старые тесты | Сверьте файлы, маски и активные наборы после загрузки ZIP. |

Справочник: [документация администратора](https://admin.contest.yandex.ru/docs/ru/), [проверка своим скриптом](https://admin.contest.yandex.ru/docs/ru/examples/advanced-usage/default-tests-for-language).
