# Юнит-тесты функции на Python

[Условие для участника](statement.md) · [Сборка и импорт задачи](../_packaging/README.md).

Используйте рецепт для проверки функций участника тестами unittest с разной стоимостью проверок.

## Что сдаёт участник

Python-модуль с функцией `evaluate_expression(text)`. Функция вычисляет выражения с операциями `+`, `-`, `*`, `/`; при делении на ноль должна вызывать `ZeroDivisionError`. Образец — [expression.py](expression.py).

Сборка сохраняет посылку под именем `expression.py`. [run_tests.py](run_tests.py) импортирует модуль, запускает тесты и последней строкой stdout печатает сумму баллов. Чекер читает эту строку.

## Настройте задачу

Выберите `PROBLEM_WITH_CHECKER`, компилятор `make` и образ с Python. Дополнительные Python-пакеты этому примеру не нужны.

| Настройка | Значение |
| --- | --- |
| Ввод | Не используется, stdin выключен |
| Вывод | stdout включён; отдельный файл не задавайте |
| Файлы компиляции | `Makefile`, `build.sh` |
| Файлы запуска | `run.sh`, `run_tests.py` |
| Тип чекера | `TESTLIB_EXITCODE_CHECKER`, «Чекер выставляет баллы» включено |
| Окружение и файл чекера | Python; `score.py` |
| Постпроцессор | Не нужен |
| Тесты | Одна пустая пара `tests/01` и `tests/01.a` |
| Монитор | `SCORING` |

Не добавляйте образец `expression.py` в файлы запуска: вместо него должен использоваться модуль участника. В Python-окружении запускайте чекер `score.py` напрямую; shell-обёртка `check_py` предназначена для окружений с запуском по shebang.

## Настройте баллы

За группу тестов сложения, вычитания и умножения начисляется по 1 баллу, за деление — 2. Максимум — 5. Группа приносит баллы, только если проходят все её проверки.

Чекер возвращает OK при положительном балле, даже если часть unittest-проверок не прошла. Ноль и пустой вывод дают WA, нечисловая последняя строка — PE.

Для своей задачи замените тесты и веса в `run_tests.py`. Сохраните последнюю строку с числом и не перенаправляйте stdout в файл. По умолчанию `DEADLINE = None` в `score.py`: штрафа нет. Если включаете дедлайн, согласуйте время окружения; каждый начатый день просрочки снижает множитель на 0.1 до минимума 0.5.

## Проверьте результат

Отправьте образец: ожидайте OK/5. Реализация только сложения должна получить OK/1, полностью неверная функция — WA/0. В отчёте включите вывод решения, если хотите показывать лог unittest.

Если балл потерян, проверьте последнюю строку stdout. Если чекер выдаёт SyntaxError, убедитесь, что выбран `score.py`, а не shell-обёртка.

## Соберите и загрузите файлы

Из корня репозитория выполните:

```sh
python _packaging/package_recipe.py --check run-unittest-python
python _packaging/package_recipe.py run-unittest-python
```

Загрузите `dist/run-unittest-python.zip` в корень файлов задачи. Назначьте роли файлов из таблицы выше в указанном порядке; архив сам не применяет настройки. Скрипты храните с LF. Сверьте старые файлы и активные тесты: ZIP не удаляет отсутствующие в нём пути.
