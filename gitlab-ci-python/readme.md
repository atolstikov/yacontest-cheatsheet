# Python-функция с проверкой в GitLab CI

Статус: шаблон проекта и CI с локально проверяемым решением. Интеграция с Контестом не подключена и не проверена.

Тип задачи — `GITLAB_PROBLEM`. **Доступ к этому типу ограничен:** организатор должен запросить подключение через поддержку. Официальное описание ограничения и форматов сдачи — [«Тип задачи»](https://admin.contest.yandex.ru/docs/ru/problem/main-problem#type).

## Подготовьте репозиторий

1. Создайте отдельный GitLab-проект для учебного задания.
2. Скопируйте в его корень `solution.py`, `test_solution.py`, `requirements.txt` и скрытый файл `.gitlab-ci.yml` из этой папки. Авторское решение `author_solution.py` оставьте у организатора.
3. Убедитесь, что у проекта есть GitLab Runner, способный запускать CI-задания с указанным Docker-образом. Обычный shell-runner потребует отдельной настройки окружения.
4. Укажите участникам [условие](statement.md). Стартовая функция намеренно не реализована, поэтому первая проверка должна завершиться ошибкой.

CI устанавливает pytest, проверяет функцию и сохраняет JUnit-отчёт `report.xml`. Сам по себе этот отчёт не отправляет баллы в Контест.

## Проверьте локально

Из этой папки выполните:

```sh
python -m pip install -r requirements.txt
python -m pytest -q test_solution.py
```

Для положительной проверки временно замените содержимое `solution.py` кодом из `author_solution.py`: должны пройти все 9 проверок. Верните стартовую заготовку перед выдачей задания. Пустая реализация должна провалить проверки; отрицательные границы, совпадающие границы и неправильный порядок границ проверяются отдельно.

## Подключите Контест

После получения доступа согласуйте с поддержкой доступный GitLab-инстанс, права интеграции, Runner и способ возврата результата CI. Создайте `GITLAB_PROBLEM` и выберите формат ответа: персональный репозиторий либо редактор/загрузка файла с проверкой через CI.

По [официальной документации](https://admin.contest.yandex.ru/docs/ru/problem/main-problem#type), формат ответа нельзя менять после создания репозиториев. Выберите его до выдачи задания.

Настройте передачу вердикта и балла средствами подключённой интеграции. Этот шаблон не содержит токенов, URL служебных API или предполагаемого callback-протокола. Публичные тесты подходят для обучения; для зачётной проверки обеспечьте запуск проверок из доверенного источника, а не только CI-конфигурации, которую может менять участник.

## Проверьте связку целиком

Проверьте обычным аккаунтом участника создание/открытие репозитория или форму сдачи, запуск CI, поступление результата в Контест и отображение балла в мониторе. Отправьте правильное и ошибочное решения. До такой проверки не считайте интеграцию готовой.

Готовый ZIP задачи не создаётся: настройки внешнего GitLab и CI не переносятся нашим упаковщиком. Клонирование задачи тоже требует доступной интеграции и проверки внешних связей.

Справочные материалы GitLab: [CI/CD YAML](https://docs.gitlab.com/ci/yaml/) и [JUnit-отчёты](https://docs.gitlab.com/ci/testing/unit_test_reports/).
