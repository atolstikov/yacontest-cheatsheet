# Ноутбук с проверкой в отдельном ядре

Статус: заготовка ноутбука, локальная проверка и шаблон GitLab CI. Запуск внутри Jupyter-задачи Контеста не проверен.

Тип задачи — `JUPYTER_PROBLEM`. **Доступ к этому типу ограничен:** подключение нужно согласовать с поддержкой. Ограничения и требования описаны в официальном разделе [«Тип задачи»](https://admin.contest.yandex.ru/docs/ru/problem/main-problem#type).

## Подготовьте пример

Выдайте участникам [условие](statement.md) и `solution.ipynb`. Участник реализует функцию статистики списка измерений. В стартовом ноутбуке нет выходных данных или счётчиков выполнения; функция намеренно вызывает `NotImplementedError`.

`author_solution.py` содержит контрольную реализацию для организатора. Не выдавайте её вместе со стартовой заготовкой. В GitLab-проект для проверки скопируйте `solution.ipynb`, `check_notebook.py`, `checks.py`, `requirements.txt` и `.gitlab-ci.yml` в корень.

## Проверьте локально

Создайте отдельное Python-окружение и выполните из этой папки:

```sh
python -m pip install -r requirements.txt
python -m ipykernel install --user --name python3
python check_notebook.py solution.ipynb --output executed.ipynb
```

Для положительной проверки замените тело функции в ноутбуке реализацией из `author_solution.py`. Стартовая заготовка должна завершиться ошибкой; правильная реализация должна пройти все пять проверок.

`check_notebook.py` запускает ноутбук в новом ядре `python3`, затем выполняет проверки из `checks.py`. Удаление демонстрационной ячейки из ноутбука не убирает эти проверки. Максимум на выполнение одной ячейки — 60 секунд. Скрипт возвращает 0 при успехе и 1 при ошибке; при `--output` сохраняет исполненный ноутбук, включая диагностику ошибки. Исходный ноутбук не перезаписывается.

В CI используется тот же скрипт. Артефакт `executed.ipynb` помогает разбирать ошибки, но сам по себе не передаёт баллы в Контест. Перед выдачей задания восстановите стартовый ноутбук и очистите вывод.

## Подключите Контест

1. Запросите доступ к `JUPYTER_PROBLEM` и согласуйте GitLab-интеграцию с поддержкой.
2. Подготовьте доступный участникам JupyterHub, ядро Python и окружение с зависимостями задания. CI-образ из примера не разворачивает JupyterHub.
3. Настройте репозиторий и проверку согласно контракту подключённой интеграции. Уточните, как изменения из JupyterLab попадают в GitLab и какое действие участника запускает проверку.
4. Настройте передачу вердикта и балла в Контест и опишите участнику способ сдачи.
5. Проверьте весь путь обычным аккаунтом участника: открытие JupyterLab, доступ к файлам, сохранение, запуск проверки, получение результата и балл в мониторе.

По [официальной документации](https://admin.contest.yandex.ru/docs/ru/problem/main-problem#type), все Jupyter-задачи одного соревнования должны использовать один и тот же инстанс GitLab.

Шаблон не содержит развёртывания JupyterHub, настройки авторизации или неподтверждённого API передачи баллов. Для зачётной проверки храните проверяющий код в доверенном источнике, отдельно от изменяемого участником ноутбука и CI-конфигурации. Публичные проверки в этой папке предназначены для учебного примера.

Импортируемый ZIP не создаётся: внешние GitLab, JupyterHub и их связи не переносятся нашим упаковщиком. Клонирование задачи также требует проверки этих связей.

Документация компонентов: [JupyterHub](https://jupyterhub.readthedocs.io/en/stable/) и [NBClient](https://nbclient.readthedocs.io/en/latest/).
