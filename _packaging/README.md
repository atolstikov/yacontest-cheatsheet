# Сборка и импорт задач

Выберите способ переноса:

- **Клонирование.** Запросите у владельца сборника доступ к нужной задаче. Откройте её в админке и выберите «Действия → Клонировать задачу». Правьте свою копию.
- **Импорт самостоятельной задачи.** Соберите YANDEX-пакет из исходников по инструкции ниже. Доступ к исходной задаче в Контесте не нужен.
- **Загрузка только файлов.** Используйте `package_recipe.py`, если задача уже создана и вы хотите назначить настройки вручную.

Шаблоны [GitLab CI](../gitlab-ci-python/readme.md) и [Jupyter](../jupyter-notebook/readme.md) требуют внешних интеграций и не входят в `--all`. Их подключение описано отдельно; [официальное ограничение доступа](https://admin.contest.yandex.ru/docs/ru/problem/main-problem#type) действует и при клонировании.

## Соберите импортируемый пакет

Из корня репозитория установите зависимость для рендеринга Markdown и соберите выбранный рецепт:

```sh
python -m pip install -r _packaging/requirements.txt
python _packaging/package_problem.py --check db-sqlite
python _packaging/package_problem.py db-sqlite
```

Результат — `dist/db-sqlite.yandex.zip`. Можно перечислить несколько рецептов. Для всех семи используйте:

```sh
python _packaging/package_problem.py --check --all --assets ./contest-assets
python _packaging/package_problem.py --all --assets ./contest-assets
```

Для ML подготовьте `contest-assets/ml-score-prediction/true_answers.csv`: один столбец из 3140 меток с заголовком. Каталог `--assets` может находиться вне репозитория; относительный путь считается от текущего рабочего каталога. Если данные находятся внутри репозитория, исключите их через `.git/info/exclude`. Без этого файла сборка ML завершится ошибкой. Остальным рецептам `--assets` не нужен.

Сборщик сначала проверяет всю выбранную партию. Если хотя бы один рецепт некорректен, новые архивы этой партии не записываются. Старые архивы в `dist/` остаются: проверяйте успешное завершение команды перед загрузкой.

## Импортируйте в Контест

1. Откройте [Задачи](https://admin.contest.yandex.ru/problems).
2. Нажмите **Загрузить задачу** и выберите формат **YANDEX**.
3. Загрузите `dist/<рецепт>.yandex.zip` и дождитесь завершения операции.
4. Откройте созданную задачу. Проверьте условие, файлы, тесты и настройки по README рецепта. Правьте эту самостоятельную копию внутри системы.
5. Добавьте задачу в свой набор соревнования. Выберите компилятор `make` и образ с зависимостями рецепта; настройте монитор `SCORING`, стратегию зачётной посылки и доступ к отчёту.
6. Для частичного зачёта отключите прерывание при первой ошибке в задаче и наборах тестов. Проверьте правильную, неверную и частично верную посылки через интерфейс участника.

Загружайте этот архив через **Загрузить задачу**, а не на вкладке «Файлы» существующей задачи. Результат — новая задача, которая ещё не добавлена в ваше соревнование. Настройки соревнования и доступы архив не переносит.

## Что входит в пакет

- `meta.json` в родном формате YANDEX: название, тип, лимиты, роли файлов, чекер, постпроцессор, наборы тестов и варианты ответа для тестовой задачи.
- Условие из `statement.md`: исходный Markdown, HTML и разделы условия.
- Только явно перечисленные файлы рецепта и пары тестов. Для вопроса с вариантами тест генерируется из `example.json`.

Настройки редактируйте в `import.json`, роли и состав файлов программных задач — в `package.json`. Порядок файлов в ролях сохраняется. Импортируемые условия используют Markdown без встроенного HTML; формулы в этих примерах записаны обычным текстом.

В ML-пакете числовой результат `score.py` проверяет переносимый Python-адаптер `score_file.py`. Он принимает в том числе 0 баллов, отклоняет текст ошибки и нечисловые значения. Это позволяет собирать пакет без компиляции C++ под Linux. Файловый ZIP по-прежнему содержит исходный `pointscmp.cpp` для настройки C++-чекера вручную.

ZIP не содержит историю посылок, ID исходных задач, авторов, права доступа или связи с наборами. Авторские решения не включаются. Архив ML содержит переданные скрытые ответы: передавайте его организаторам, а не участникам.

Готовые архивы не хранятся в Git: `dist/` исключён. Для другой папки результата используйте `--output DIR` и исключите её самостоятельно.

## Обновите только файлы

```sh
python _packaging/package_recipe.py --check db-sqlite
python _packaging/package_recipe.py db-sqlite
```

`dist/db-sqlite.zip` содержит только файлы. Загрузите его в корень файлов уже созданной задачи и назначьте роли вручную по README рецепта. Он не переносит условие и настройки и не удаляет оставшиеся старые файлы. Для этого режима сторонние Python-пакеты не нужны.
