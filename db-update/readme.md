# Изменение SQLite-базы

Используйте рецепт, чтобы проверять изменение данных, а не только вывод SQL-запроса.

## Что сдаёт участник

Python-модуль с функцией `get_result(name)`. Функция открывает базу по переданному пути, удаляет боевики с чётной продолжительностью и сохраняет изменения. Остальные строки Films и таблица genres должны сохраниться. Образец — [solution.py](solution.py).

[test.py](test.py) копирует исходную БД во временный каталог, вызывает функцию и записывает SQL-дамп в `output.txt`. Чекер восстанавливает дамп в памяти и сравнивает содержимое Films и genres с эталоном. Не требуйте от участника печатать дамп самостоятельно.

## Настройте задачу

Выберите `PROBLEM_WITH_CHECKER`, компилятор `make` и образ с Python и flake8. Модуль sqlite3 входит в стандартную библиотеку Python.

| Настройка | Значение |
| --- | --- |
| Ввод | stdin включён; тест содержит имя базы |
| Вывод | файл `output.txt`, stdout выключен |
| Создание файлов | Разрешено |
| Файлы компиляции | `Makefile`, `build.sh`, `check.py` |
| Файлы запуска | `run.sh`, `test.py`, `films.db`, `films1.db`, `films2.db` |
| Тип чекера | `TESTLIB_EXITCODE_CHECKER`, «Чекер выставляет баллы» выключено |
| Окружение и файлы чекера | Python; `compare_result.py` первым, затем все три БД |
| Постпроцессор | Python; `postprocessor.py` |
| Тесты | `tests/01`–`tests/03`, маска `tests/{01-}`, ответы `*.a` |
| Монитор | `SCORING` |

Исходные runtime-файлы могут быть доступны только для чтения. Сохраните создание рабочей копии в `test.py`; передавайте участнику путь к ней. Базы положите также в файлы чекера.

## Настройте баллы

По умолчанию постпроцессор начисляет 100 за все три теста и 0 иначе. Для частичного зачёта установите `DIFFERENT = True` и отключите оба прерывания тестирования при первой ошибке.

## Проверьте результат

Отправьте образец: ожидайте OK/100. Отправьте функцию с `pass`: ожидайте WA/0. Проверьте также решение, удаляющее лишние строки: оно должно получить WA.

При read-only ошибке проверьте создание временной копии. При WA сверьте сохранение транзакции и неизменность остальных данных. При пустом выводе проверьте выходной файл `output.txt` и разрешение создания файлов.

## Соберите и загрузите файлы

Из корня репозитория выполните:

```sh
python _packaging/package_recipe.py --check db-update
python _packaging/package_recipe.py db-update
```

Загрузите `dist/db-update.zip` в корень файлов задачи. Назначьте роли файлов из таблицы выше в указанном порядке; архив сам не применяет настройки. Скрипты храните с LF. Сверьте старые файлы и активные тесты: ZIP не удаляет отсутствующие в нём пути.
