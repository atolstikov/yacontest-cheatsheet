# Вопрос с вариантами ответа

[Условие для участника](statement.md) · [Сборка и импорт задачи](../_packaging/README.md).

Используйте рецепт для одного или нескольких правильных вариантов. Участник выбирает пункты в интерфейсе; код и компилятор для сдачи не нужны.

## Подготовьте пример

Возьмите условие из [statement.md](statement.md) и варианты из [example.json](example.json). JSON задаёт варианты для сборщика YANDEX-пакета; при ручной настройке перенесите их в форму админки.

В примере нужно отметить два верных утверждения о SQLite: поддержку SQL и возможность открыть базу через `:memory:`. Правильные пункты — 1 и 3.

## Настройте задачу

1. Создайте задачу типа `TEST_PROBLEM`.
2. Выберите «Несколько вариантов». Для единственного верного пункта используйте «Один вариант».
3. Введите формулировки и отметьте правильные пункты в столбце «Верно?».
4. Добавьте условие в Markdown + KaTeX и укажите правила оценивания.
5. Выберите `STANDARD_CHECKER` / `cmp_file` для точного совпадения.
6. Для оценки 100/0 загрузите [postprocessor.py](postprocessor.py), выберите его первым файлом постпроцессора и назначьте Python-окружение. Установите максимальный балл 100.
7. Выберите монитор соревнования `SCORING`, сохраните изменения и проверьте форму участника.

Контест создаёт тест из вариантов автоматически. Локальная папка tests/ не требуется. Для автоматического переноса соберите `python _packaging/package_problem.py test-problem` из корня репозитория и импортируйте `dist/test-problem.yandex.zip` в формате YANDEX. Варианты и постпроцессор войдут в пакет. При ручной настройке введите варианты в форме и загрузите постпроцессор отдельно.

## Настройте баллы

Стандартный чекер даёт OK при полном совпадении выбранных и правильных пунктов; лишний или пропущенный пункт даёт WA. Постпроцессор начисляет 100 при прохождении всех тестов и 0 иначе. Он меняет балл, но не вердикт. Одного поля «Максимальный балл» недостаточно для гарантированного начисления — проверьте итог контрольной посылкой.

Для частичного зачёта замените стандартный чекер своим типа `TESTLIB_EXITCODE_CHECKER` и включите «Чекер выставляет баллы». При вердикте OK первое число первой строки вывода задаёт балл теста. Согласуйте итоговый постпроцессор с этой формулой: текущий вариант 100/0 не сохраняет частичный балл.

В качестве примеров формул используйте [at-testlib](https://github.com/atolstikov/testlib):

- `checkers/points_Jaccard_index.py` — размер пересечения выбранных и верных пунктов, делённый на размер объединения;
- `checkers/points_share_of_checked_right.py` — доля правильно отмеченных и правильно не отмеченных пунктов.

Эти чекеры — отдельный вариант настройки. Перед использованием проверьте формат входных файлов и начисление баллов на своих вариантах.

## Проверьте результат

| Выбор участника | Ожидаемый результат примера |
| --- | --- |
| Пункты 1 и 3 | OK/100 |
| Все три пункта | WA/0 |
| Только пункт 1 | WA/0 |

Если правильный ответ даёт OK/0, проверьте привязку и окружение постпроцессора. При своём чекере дополнительно проверьте передачу баллов и формулу агрегации.
